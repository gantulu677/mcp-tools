# ChatGPT Native MCP Tools

This repository implements a ChatGPT Native orchestrator with a custom Supabase MCP server.

## Architecture

- ChatGPT Native performs reasoning, product selection, creative direction, prompt authoring, and native image generation.
- Supabase Edge Function exposes data and workflow tools; it does not call an image-generation API.
- Supabase Postgres stores product specifications and completed post metadata.
- Supabase Storage stores the original brand logo and finalized images.

## MCP tools

| Tool | Purpose |
| --- | --- |
| `list_products` | List active products for ChatGPT to choose from. |
| `get_product_details` | Retrieve full specifications for one product. |
| `generate` | Validate creative variables and build the final prompt. Does not generate an image. |
| `finalize_image` | Validate a ChatGPT image attachment, overlay the original PNG logo, and upload the final PNG. |
| `save_post` | Persist creative metadata and the final public image URL in `make_post`. |

## Image requirements

- Final canvas: 1080 × 1350 (4:5).
- The image is generated by ChatGPT Native without a logo.
- The original logo is read from Storage bucket `apple`, object `logo.png`.
- The logo is composited in the top-left corner.
- Final output is PNG in the public Storage bucket `image`.

## Database

Apply migrations in `supabase/migrations` in timestamp order.

- `public.products`: product catalog and JSONB specifications.
- `public.make_post`: final creative metadata, image URL, and Storage path.
- `public.generated_images`: legacy upload metadata table; retained for compatibility.

RLS is enabled on the new public tables. Direct access is revoked from `anon` and `authenticated`; the Edge Function accesses them using server-side Supabase credentials.

## Edge Function configuration

The function is configured with `verify_jwt = false` because this MCP endpoint uses its own bearer-token authentication. Before deploying, configure the following secret in Supabase Edge Function secrets:

- `AGENT_TOOLS_BEARER_TOKEN`: a high-entropy random secret (at least 32 characters).

Never commit the token or expose it to browser code. Requests must include:

```http
Authorization: Bearer <AGENT_TOOLS_BEARER_TOKEN>
```

The function fails closed with HTTP 503 when the secret is absent or too short, and HTTP 401 for an invalid token.

Supabase automatically provides `SUPABASE_URL` and the project server secret key. Do not expose the service-role/secret key to ChatGPT UI or browser code.

## Deployment checklist

1. Apply database migrations.
2. Set `AGENT_TOOLS_BEARER_TOKEN` in Supabase Function secrets.
3. Run a Deno type-check / local Edge Runtime test for `supabase/agent-tools/index.ts`.
4. Deploy `agent-tools` with `verify_jwt = false`.
5. Configure the same bearer token in the ChatGPT MCP connection.
6. Test all five tools, including the logo overlay and saved `make_post` row.

Do not deploy before the bearer token has been configured. The function intentionally fails closed without it.
